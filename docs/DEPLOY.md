# Запуск и готовность к публикации

Из локальной доработки 19.10.2026 публикация не выполнялась. Файлы и проверки готовы для
следующего отдельного этапа публикации. Не считайте наличие домена в конфигурации его
регистрацией, подтверждением владения или настройкой DNS.

## 1. Выбор модели контакта

### Статический сайт — текущий безопасный вариант

1. `PUBLIC_FORM_ENDPOINT=vk`, `CONTACT_FORM_ENABLED=false`.
2. Подтвердить URL ВКонтакте в `src/data/site.ts`; сейчас он предоставлен владельцем.
3. Публиковать `dist/client`. Никакой сборщик обращений для этой модели не нужен.
4. Посетитель пишет во внешнем сервисе, по его правилам; на сайте нет ложного сообщения
   «заявка отправлена», полей имени и телефона или сохранения черновиков.

Email-режим доступен только после подтверждения личного email в `site.ts`. Телефон и адрес
не подменяются контактами прежнего работодателя.

### Собственная форма — только после организационной готовности

Нужен Node ≥22.22.0, HTTPS и постоянный приватный диск. До включения оператор должен:

- подтвердить сведения и порядок обработки, основания, локализацию и применимые обязанности;
- определить допущенных лиц, резервирование, удаление/сроки и способ обработки запросов субъектов;
- обеспечить регулярный просмотр записей и контроль работоспособности, а не просто создать каталог;
- проверить размещение и основание передачи внешнему обработчику, если используется вебхук;
- утвердить юридические документы версии 1.1 и условия консультации;
- проверить доставку тестового обращения от браузера до ответственного человека.

Пример **после** выполнения этих условий (адрес домена заменить):

```bash
# Каталог должен принадлежать пользователю Node-процесса, быть непубличным и иметь режим 0700.
mkdir -p /var/lib/kochevinov/leads
chmod 700 /var/lib/kochevinov/leads

PUBLIC_SITE_URL=https://your-confirmed-domain.example BASE_PATH=/ PUBLIC_NOINDEX=true \
  PUBLIC_FORM_ENDPOINT=/api/contact CONTACT_FORM_ENABLED=true \
  LEADS_DIR=/var/lib/kochevinov/leads npm run build

HOST=0.0.0.0 PORT=4321 CONTACT_FORM_ENABLED=true \
  LEADS_DIR=/var/lib/kochevinov/leads npm start
```

В build-окружении нужны все три настройки UI; в runtime нужны флаг и каталог.
Node сам не читает `.env`. Передайте окружение через сервис-менеджер/контейнер или используйте
подходящий способ загрузки файла переменных. В serverless/контейнере без постоянного тома
локальные записи могут пропасть — такой хостинг нельзя считать готовым приёмником.

### Что именно делает API

- Private JSONL: `LEADS_DIR/YYYY-MM-DD.jsonl`, права файла 0600, каталога 0700.
- До ответа `ok: true` запись добавлена и синхронизирована с диском.
- Нет документов/вложений; сообщение ограничено 600 символами, тело запроса 8 КБ в байтах.
- Не записывает IP, cookie, browser ID, query или fragment referrer.
- `LEADS_WEBHOOK_URL` и `LEADS_WEBHOOK_TOKEN` — только серверные переменные; `PUBLIC_` недопустим.
- Вебхук: HTTPS, без переходов по редиректам, таймаут 5 с; HTTP-ошибки тоже считаются сбоем.
- При сбое уведомления уже сохранённая запись остаётся принятой. В лог попадают статус/номер
  записи, не текст обращения, URL вебхука или токен. Нужны мониторинг и ручной разбор сбоев.
- Автоматической почтовой отправки, CRM, повторной доставки и удаления по расписанию нет.
  Это обязанности отдельно настроенной эксплуатации; политики не утверждают обратного.
- Лимит частоты — в памяти одного процесса, сбрасывается при перезапуске. За несколькими
  процессами/прокси проверьте реальный clientAddress и настройте отдельную edge-защиту.
  Не доверяйте произвольному X-Forwarded-For от внешнего клиента.

Не публикуйте `.data`, JSONL, резервные копии, логи с данными или приватные фотографии.
Доступ к диску и административным интерфейсам не должен быть открыт через веб-сервер.

## 1a. Что должно быть в сборке до публикации

- `public/og/*.png` — персональные картинки; пересобрать после правок заголовков: `npm run og`.
- `public/memos/*.pdf` — памятки; пересобрать после правок текста: `npm run memos`.
- `/rss.xml` и `/search-index.json` создаются на этапе `astro build`; отдельных настроек не требуют.
- Аналитика выключена, пока не заданы `PUBLIC_ANALYTICS_PROVIDER` и `PUBLIC_ANALYTICS_DOMAIN`.
  Включать только вместе с обновлением политики и уведомления; Plausible/Umami — без cookie.
- Telegram-канал не подключён: адреса канала нет, выдумывать его нельзя. RSS уже отдаёт
  разборы, его можно использовать для автопостинга после создания канала.

## 2. Домен и индексация

1. Подтвердить домен и хостинг с владельцем; `kochevinov.ru` пока лишь исходное предположение.
2. Настроить DNS, HTTPS и постоянный адрес; задать `PUBLIC_SITE_URL` без завершающего `/`.
3. Указать `BASE_PATH=/` или фактический подкаталог. Сборки в корне и `/LAWS` проверяются отдельно.
4. Проверить canonical, OG и JSON-LD на том же адресе через `npm run check:build` с `EXPECT_SITE`
   и `EXPECT_BASE`. Серверные заголовки на CDN/Pages нужно настраивать средствами хостинга.
5. Только после утверждения портретов, текстов и контактов решить вопрос с
   `PUBLIC_NOINDEX=false`. По умолчанию noindex; временный `*.github.io` всегда noindex.

Переключение индексации не регистрирует домен, не создаёт почтовые ящики и не подключает
поисковые кабинеты. Эти операции в доработке не выполнялись.

## 3. Временный GitHub Pages

Workflow `.github/workflows/deploy-pages.yml` собирает статику с `/LAWS`, прямым VK и noindex.
Публикуется `dist/client`, добавляется `.nojekyll`; Node API в Pages отсутствует.

Сборка запускается из любой ветки, но деплой дополнительно контролирует окружение
`github-pages`. При правиле только `main` публикация из рабочей ветки блокируется, даже если
код workflow разрешает все ветки. Изменение этого правила требует прав владельца:
Settings → Environments → github-pages → Deployment branches and tags.

Все разрешённые ветки публикуются по одному адресу, новый деплой заменяет предыдущий:
это не отдельные preview-сайты. Для проверки используйте локальное/сессионное превью,
а для следующей публикации — новую разрешённую coding-сессию и ревью изменений.

## 4. Аналитика

Провайдер не выбран, внешние запросы и счётчики отсутствуют. Локальные `law:goal` не являются
измерением посещаемости. Не включайте рекламные/аналитические скрипты до согласования
поставщика, условий обработки, изменений политики и применимого выбора пользователя.
