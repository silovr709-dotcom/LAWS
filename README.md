# Сайт адвоката Юрия Кочевинова

Персональный сайт: уголовно-правовая защита, Тверь и работа по России. Редакционный дизайн:
бордовый / молочный / приглушённое золото, Cormorant Garamond и Golos Text. Без вымышленных
дел, цен, контактов, отзывов и гарантий результата.

**Astro 7 + TypeScript**, пререндеренные страницы и необязательный Node API. Клиентских
UI-фреймворков и внешних аналитических счётчиков нет.

## Запуск и проверки

Требования: **Node.js ≥ 22.22.0**, npm ≥ 9.6.5.

```bash
npm ci
npm run dev         # 0.0.0.0:4321, поддерживаются preview-хосты *.e2b.app
npm run check       # типы и Astro
npm test            # API, контент и изображения; используются только тестовые данные
npm run build       # dist/client + dist/server
npm run check:build # ссылки, SEO, JSON-LD, изображения, контактный режим
npm run og          # персональные OG-картинки 1200×630 в public/og/
npm run memos       # PDF-памятки в public/memos/ (нужен Chromium, см. docs/QA.md)
HOST=0.0.0.0 PORT=4321 npm start
```

`npm start` сам по себе не загружает `.env`: переменные нужны в окружении процесса.
Необязательные браузерные проверки — [docs/QA.md](docs/QA.md).

## Где менять содержание

- `src/data/site.ts` — подтверждённые факты, контакты и основные тексты.
- `src/data/services.ts` — подробное содержание направлений.
- `src/data/legal.ts` — единая версия и дата документов и записи согласия.
- `src/content/articles/` и `src/content/cases/` — Markdown, схемы в `src/content.config.ts`.
- `src/data/documents.ts` — образцы заявлений: правовая основа, адресат, срок и полный текст.
- `src/styles/global.css` — основа; `premium.css` — обновлённая композиция и адаптив.

Пустой телефон, email и адрес не заменяются контактами прежнего места работы. Для их
добавления нужно подтверждение владельца: [docs/DATA-CHECKLIST.md](docs/DATA-CHECKLIST.md).
Тексты направлений и юридические материалы требуют вычитки адвокатом.

### Портреты и галерея

Владелец предоставил фотографии **только как образцы внешности**. Они не являются файлами
для публикации. Для сайта созданы семь изображений по этим образцам: два основных портрета и
пять кадров галереи. Владелец подтвердил сходство 20.10.2026 и попросил **не подписывать
изображения как ИИ**; подписи и alt удалены, но изображения не выдаются за документальную
съёмку конкретного события — на странице «Обо мне» это сказано прямо.

- `assets/generated-portraits/` — только новые сгенерированные исходники, не референсы.
- `public/images/yuriy-*` — AVIF/WebP 320/640/960 px и отдельная лицевая обрезка для аватара.
- `public/og/og-default.{png,svg}` — одна согласованная композиция 1200×630 с личным портретом.
- `npm run portraits` — воспроизводимая подготовка файлов из сгенерированных исходников.

Компонент `Portrait` использует `picture/srcset`, размеры и приоритет первой фотографии.
В галерее на `/ob-advokate/` — пять кадров 4:5 (AVIF/WebP 320/640/960). У OG шрифты переведены
в контуры, внешние шрифты и системные гарнитуры для его генерации не нужны.
Подробнее: [docs/IMAGES.md](docs/IMAGES.md).

### Аварийные страницы и инструменты

`/srochno/`, `/situacii/*`, `/sroki/` и `/memos/*` — статические страницы без серверной логики.
Калькуляторы считают в браузере (`src/lib/deadlines.ts`), ничего не отправляют и не сохраняют.
Памятки собираются из `src/data/memos.ts` в PDF (`npm run memos`) и коммитятся в `public/memos/`.
Конструктор первого сообщения на `/bezopasnaya-peredacha-dokumentov/` формирует текст локально:
посетитель сам решает, когда открыть чат.

Персональные OG-картинки генерируются из заголовков страниц (`npm run og`) и коммитятся в
`public/og/`. Если файла для страницы нет, `BaseHead` подставляет общую картинку. Шрифты для
рендера — TTF из `scripts/fonts/` (OFL), потому что resvg не читает WOFF2.

### Образцы документов

`npm run documents` пересобирает PDF из `src/data/documents.ts` (нужны опциональные
инструменты из [docs/QA.md](docs/QA.md)). Готовые файлы лежат в `public/documents/` и
коммитятся: сборка на GitHub Pages браузер не запускает. Ссылки на PDF строятся через
`withBase()`, поэтому работают и в подкаталоге `/LAWS/`.

### Дела и публикации

Дела не импортируются по совпадению фамилии. Для публикации нужны подтверждение участия,
обезличивание, правовое основание и личное одобрение адвоката:
[docs/PRACTICE-PUBLISHING.md](docs/PRACTICE-PUBLISHING.md).

Первый материал с `draft: false` включает блок практики и пункт навигации. Пока включён
общесайтовый noindex, он действует и на такие материалы. У дела `draft` по умолчанию `true`.
У статей — `false`; указывайте даты, источники и начинайте внутренние заголовки с `##`.

## Контакт: три явных режима

**По умолчанию — прямая ссылка ВКонтакте, без анкеты и сбора сообщения сайтом.** Посетителю
не нужно вводить имя и телефон перед переходом и повторять текст во внешнем диалоге.
Переход не означает отправки сообщения; это объясняется рядом с кнопкой.

| Настройка при сборке | Результат |
|---|---|
| `PUBLIC_FORM_ENDPOINT=vk` или не задано | Прямая ссылка `site.vkChat` |
| `PUBLIC_FORM_ENDPOINT=mailto` | Почтовая программа, только если в `site.ts` подтверждён email; иначе VK |
| `PUBLIC_FORM_ENDPOINT=/api/contact` + `CONTACT_FORM_ENABLED=true` + абсолютный `LEADS_DIR` | Настоящая серверная форма, только для Node-размещения |

Никакие поля не появляются от одного лишь наличия API в исходниках. API на запущенном
Node-сервере тоже отключён без `CONTACT_FORM_ENABLED=true` и допустимого `LEADS_DIR`.
На GitHub Pages серверный режим не работает.

### Необязательный API

`POST /api/contact` проверяет origin, JSON, потоковый размер в байтах (8 КБ), поля, согласие
и его версию. Есть honeypot, минимальное время заполнения и in-memory лимит 5 запросов/час
на адрес клиента. Это базовая защита, а не замена защите прокси или распределённому лимитеру.

После проверки запись сохраняется в приватном JSONL-файле с правами `0600` в каталоге `0700`.
Каталог задаётся абсолютным путём, вне `public/`, `dist/client` и `.git`. В запись не входят
IP, cookie, идентификатор посетителя или параметры referrer URL. Вебхук необязателен;
сетевой сбой и HTTP 4xx/5xx логируются без текста обращения и секретов. **Успех API означает
локальное сохранение, не гарантированную доставку уведомления.**

При ошибке интерфейс не показывает ложного подтверждения и не очищает поля. Кнопка
блокирует повторный запрос; нативный checkbox и ошибки доступны с клавиатуры. Без JavaScript
отправка заблокирована и есть прямая ссылка; форма никогда не отправляет персональные данные
в GET-параметрах. Сервер не рассылает email сам.

Перед включением нужно организовать реальное получение записей, постоянный диск, доступ,
резервирование, удаление и юридически проверенную схему обработки. См. [docs/DEPLOY.md](docs/DEPLOY.md).

## Приватность и цели

Счётчики, рекламные пиксели и внешний сбор статистики **не подключены** по умолчанию.
Приватная аналитика включается только явными `PUBLIC_ANALYTICS_PROVIDER` и
`PUBLIC_ANALYTICS_DOMAIN` (Plausible или Umami, без cookie и идентификаторов) и требует
обновления политики. Без этих переменных `Analytics.astro` не выводит ни одного скрипта. Код сайта не
использует cookie, localStorage или sessionStorage. В подвале — правдивое уведомление,
а не баннер с фиктивным согласием. Правила хостинга и внешнего сервиса переписки рассматриваются отдельно.

`src/lib/events.ts` предоставляет локальное событие `law:goal` с полями `{ name, path }`:
`contact_vk`, `contact_phone`, `contact_email`, `contact_success`, `service_open`,
`situation_open`, `doc_open`, `doc_download`, `memo_view`, `memo_download`, `calc_use`,
`search_use`, `registry_check`. Сам по себе сайт эти события никуда не отправляет.
Нет сетевого отправителя, хранения, form values или идентификатора пользователя. Подключать
провайдера можно только после выбора владельцем, проверки обработки, обновления документов
и применимого механизма согласия. ID счётчиков намеренно не выдуманы.

## Домен, SEO и размещение

- Все локальные URL проходят через `withBase()`. Canonical, OG и JSON-LD используют один
  `canonicalUrl()`; manifest использует относительные `start_url`, `scope` и пути иконок.
- **По умолчанию noindex**. Индексация включается только явным `PUBLIC_NOINDEX=false` после
  утверждения домена, содержания и запуска. Домены `*.github.io` остаются noindex независимо
  от этого переключателя.
- `kochevinov.ru` в исходной конфигурации — неподтверждённое предположение, не регистрация
  домена. Перед запуском задайте подтверждённый `PUBLIC_SITE_URL` и `BASE_PATH`.
- Серверные security-заголовки: `src/middleware.ts`. На статическом хостинге настраивайте
  заголовки на стороне самого хостинга: Node middleware там не исполняется.

### Временная сборка для GitHub Pages

```bash
PUBLIC_SITE_URL=https://silovr709-dotcom.github.io BASE_PATH=/LAWS \
  PUBLIC_NOINDEX=true PUBLIC_FORM_ENDPOINT=vk CONTACT_FORM_ENABLED=false npm run build
EXPECT_SITE=https://silovr709-dotcom.github.io EXPECT_BASE=/LAWS npm run check:build
```

Публикуется только `dist/client`; workflow добавляет `.nojekyll`. Из этой локальной доработки
публикация не выполнялась. Настройки окружения GitHub могут разрешать деплой только из `main`,
даже если workflow запускает сборку из любой ветки. См. [docs/DEPLOY.md](docs/DEPLOY.md).
